# Материалы для пояснительной записки

Этот файл — черновая основа разделов отчёта. Перед сдачей её необходимо сверить с требованиями кафедры и заполнить результатами ручной проверки Windows. Неподтверждённые результаты намеренно не указаны как выполненные.

## 1. Цель работы

Разработать оконное приложение на C++ для анализа использования дискового пространства файловой системы с представлением результатов в виде дерева каталогов, таблиц статистики и круговой диаграммы.

## 2. Функциональные требования

Приложение должно:
- рекурсивно обходить выбранный каталог;
- определять категории файлов;
- вычислять количество файлов и суммарный размер по категориям;
- раздельно представлять статистику текущего каталога и вложенных каталогов;
- отображать абсолютные размеры и относительные доли;
- предоставлять интерактивное дерево каталогов и список содержимого выбранного каталога;
- выполнять анализ вне GUI-потока;
- показывать прогресс, ошибки файловой системы и поддерживать отмену;
- экспортировать агрегированный результат.

## 3. Принятые архитектурные решения

Система разделена на Domain, Infrastructure, Application, Visualization и UI. Сканер строит дерево каталогов и заполняет direct-статистику. Агрегатор рассчитывает subtree-статистику снизу вверх. Контроллер управляет рабочим потоком и уведомлениями GUI. Экспорт использует уже рассчитанный результат.

Подробная схема ответственности модулей описана в ARCHITECTURE.md.

## 4. Алгоритм анализа

1. Проверить существование корневого каталога и возможность его чтения.
2. Создать корневой узел результата.
3. Выполнить итеративный обход каталогов с проверкой отмены.
4. Для файлов получить размер и определить категорию по расширению.
5. Записать количество и размер файла в direct-статистику его каталога.
6. Передавать в GUI прогресс и ошибки через callbacks/сигналы.
7. После завершения сканирования выполнить bottom-up агрегацию.
8. Отобразить дерево, статистику и диаграмму; при необходимости сохранить результат в JSON или TXT.

Символические ссылки на каталоги показываются как узлы, но их цели повторно не обходятся.

## 5. Тестирование

Автоматические тесты запускаются CTest; CI выполняет конфигурацию CMake, сборку и тесты на Ubuntu 24.04. Список проверяемых сценариев приведён в TESTING.md.

**Фактический результат CI для итогового коммита:** заполнить после завершения GitHub Actions на актуальном SHA.

**Результат ручного тестирования Windows:** заполнить после проверки в целевом окружении.

Рекомендуемая таблица результатов:

| Проверка | Ожидаемый результат | Фактический результат |
|---|---|---|
| Анализ тестового каталога | Подсчитаны файлы и размеры | Заполнить после ручной проверки |
| Direct/subtree-статистика | Значения соответствуют структуре тестового каталога | Заполнить после ручной проверки |
| Проценты | Доли ненулевой области суммируются примерно до 100% | Заполнить после ручной проверки |
| Круговая диаграмма | Секторы пропорциональны занимаемому размеру | Заполнить после ручной проверки |
| Отмена анализа | Анализ останавливается, GUI остаётся доступным | Заполнить после ручной проверки |
| Экспорт JSON/TXT | Файлы создаются и содержат агрегированный результат | Заполнить после ручной проверки |
| Ошибочный путь | Выводится ошибка, приложение не аварийно завершается | Заполнить после ручной проверки |

## 6. Ограничения

- Классификация файлов реализована по расширению; MIME и анализ сигнатур не реализованы.
- Кнопка обновления перечитывает список содержимого выбранного каталога, но не пересчитывает глобальную статистику; для обновления статистики требуется повторный полный анализ.
- Автоматический CI на Linux не заменяет проверку сборки и запуска на Windows.
- До ручной приёмки нельзя утверждать, что проверены все особенности целевого Windows-окружения.

## 7. Заключение
