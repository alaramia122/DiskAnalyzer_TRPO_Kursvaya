# Проверки и критерии приёмки

## 1. Автоматические проверки

Сборка и тесты запускаются командами:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

GitHub Actions выполняет конфигурацию CMake, сборку и CTest на Ubuntu 24.04. Успешный CI подтверждает прохождение тестов в этой среде, но не заменяет запуск приложения в Windows.

Набор тестов покрывает:
- обход тестового дерева, direct/subtree-статистику и классификацию по расширению;
- пустые каталоги и символические ссылки, если окружение позволяет создавать ссылки;
- повторную агрегацию без двойного учёта;
- отмену анализа и ошибочный корневой путь;
- экспорт JSON/TXT, ошибочные пути и сохранение существующего файла при неподдерживаемом формате;
- жизненный цикл ApplicationController, запрет конкурирующего запуска, отмену и повторный запуск;
- преобразование статистики для Direct/Subtree/Total;
- LRU-кэш, обновление записи и чтение содержимого каталога.

## 2. Ручная приёмка Windows

Проверить на Windows с установленными Qt и Visual Studio/MSVC:

1. Собрать проект с BUILD_TESTING=ON и убедиться, что сборка завершается без ошибок.
2. Запустить приложение из выходного каталога сборки.
3. Создать тестовый каталог с несколькими файлами известных размеров, файлами разных расширений, вложенной директорией и пустой директорией.
4. Запустить анализ и убедиться, что интерфейс остаётся отзывчивым, прогресс обновляется, а отмена доступна.
5. Выбрать корневой каталог и вложенные каталоги; проверить direct- и subtree-колонки.
6. Проверить абсолютные размеры и процентные доли. Для ненулевой области доли категорий должны суммироваться приблизительно до 100% с учётом округления.
7. Проверить, что круговая диаграмма отражает размер данных, а не количество файлов.
8. Открыть список содержимого, нажать «Обновить» после добавления/удаления файла и убедиться, что перечитывается локальный список. Отдельно убедиться, что статистика полного анализа не обновляется до повторного анализа.
9. Экспортировать JSON и TXT, открыть файлы и проверить наличие путей, статистики и категорий.
10. Проверить обработку недоступного/несуществующего корневого пути и доступность журнала ошибок.
11. Проверить запуск на каталоге с большим числом файлов, оценить время реакции интерфейса и потребление памяти.
12. Запустить приложение на целевой Windows-системе без открытой IDE, чтобы проверить развёртывание Qt runtime.

## 3. Фиксация результатов

Для отчёта записать:
- версию Windows, компилятор и версию Qt;
- конфигурацию сборки;
- результаты CTest;
- тестовый набор файлов и ожидаемые/фактические размеры;
- результат проверки JSON/TXT;
- скриншоты главного окна, таблицы статистики и диаграммы;
- обнаруженные ограничения или дефекты.

Ручная проверка Windows остаётся невыполненной до запуска приложения в целевом окружении.
