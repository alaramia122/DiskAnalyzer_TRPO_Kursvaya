# Генерация финального DOCX-отчёта

## Локально

Требуются Python 3.10+, пакет python-docx, LibreOffice Writer и poppler-utils (команда pdftotext). Из корня репозитория выполнить:

    python -m pip install python-docx
    python scripts/generate_final_report.py --output dist/Отчет_курсовая_ТРПО_DiskAnalyzer.docx
    mkdir -p dist/initial-render dist/preview
    libreoffice --headless --convert-to pdf --outdir dist/initial-render dist/Отчет_курсовая_ТРПО_DiskAnalyzer.docx
    python scripts/update_toc_page_numbers.py dist/Отчет_курсовая_ТРПО_DiskAnalyzer.docx dist/initial-render/Отчет_курсовая_ТРПО_DiskAnalyzer.pdf
    libreoffice --headless --convert-to pdf --outdir dist/preview dist/Отчет_курсовая_ТРПО_DiskAnalyzer.docx

Скрипт использует текущие файлы репозитория, поэтому листинги соответствуют checkout, из которого он запущен. Перед сдачей запускать генератор из проверенной версии master или из commit, который предполагается сдавать.

## Через GitHub Actions

1. Открыть вкладку Actions репозитория.
2. Выбрать workflow Generate final coursework report.
3. Нажать Run workflow и выбрать ветку, которую нужно включить в отчёт.
4. Дождаться завершения задания.
5. Скачать артефакт DiskAnalyzer-final-report из завершённого запуска.

Workflow генерирует DOCX и проверяет базовую целостность. Успешная генерация не заменяет визуальную проверку документа в Word/LibreOffice.

## Что делает генератор

- Создаёт титульный лист и обязательные разделы.
- Добавляет исходную формулировку задания.
- Включает псевдокод основных алгоритмов.
- Формирует видимое оглавление по фактическим заголовкам разделов и подразделов; отдельный шаг рендеринга PDF и `update_toc_page_numbers.py` проставляет номера страниц по фактической пагинации.
- Группирует программные единицы по видам; для каждой формирует сигнатуру, роли аргументов, назначение, выходные данные и возможные эффекты, которые необходимо сверить с телами реализации.
- Формирует таблицы сценариев тестирования, различая автоматические проверки и ручные сценарии без подтверждённого фактического прогона.
- Включает найденные .h/.cpp из src/ и tests/, CMakeLists.txt и workflow.
- Создаёт manifest с перечнем включённых файлов и проверяет наличие обязательных разделов.

## Ограничения

- Скрипт не выполняет GUI-тестирование и не получает автоматически свежий статус CI; такие факты нужно проверить отдельно.
- Программная проверка DOCX не может надёжно оценить визуальные разрывы страниц.
- При изменении текста/вёрстки повторно выполните рендеринг и `update_toc_page_numbers.py`, иначе номера страниц в оглавлении могут устареть.
- Автоматическое извлечение сигнатур и ролей аргументов не заменяет ручную сверку описания назначения и побочных эффектов с телом каждой реализации.
- Если код изменился, описания архитектуры и псевдокод необходимо сверить с изменениями.
