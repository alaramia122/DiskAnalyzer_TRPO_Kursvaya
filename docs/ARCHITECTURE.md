# Архитектура Disk Analyzer

## 1. Слои

### Domain
Содержит FileCategory, ScanStatus, FileInfo, DirectoryStatistics, DirectoryNode, AnalysisResult и интерфейсы IDirectoryScanner, IFileClassifier, IDirectoryAggregator. Базовые модели не зависят от Qt.

### Infrastructure
- FileClassifier: классификация по расширению файла.
- DirectoryScanner: итеративный обход дерева каталогов через std::filesystem.
- DirectoryAggregator: вычисление статистики поддеревьев по уже построенному дереву.
- DirectoryContentsReader: чтение непосредственного содержимого каталога для таблицы навигации.
- DirectoryCacheManager: ограниченный LRU-кэш локальных списков файлов.
- ExportManager: сериализация агрегированного результата в JSON и TXT.

### Application
AnalysisPipeline связывает scanner и aggregator, но не управляет потоками. ApplicationController отвечает за запуск фонового std::thread, запрос отмены, передачу прогресса и ошибок в Qt и уведомление о завершении.

### Visualization и UI
VisualizationModel преобразует DirectoryStatistics в значения по категориям для выбранной области. MainWindow предоставляет выбор корневого каталога, запуск/отмену, дерево каталогов, список содержимого, таблицу статистики, круговую диаграмму и экспорт.

## 2. Поток обработки

1. Пользователь выбирает корневой каталог и запускает анализ.
2. ApplicationController создаёт рабочую задачу.
3. DirectoryScanner итеративно обходит файловую систему, классифицирует файлы и обновляет direct-статистику соответствующих каталогов.
4. DirectoryAggregator проходит дерево снизу вверх и вычисляет subtree-статистику.
5. ApplicationController передаёт итоговый статус GUI. GUI читает результат только после уведомления о завершении.
6. MainWindow строит дерево и отображает статистику и диаграмму по выбранному каталогу.
7. Экспорт использует уже рассчитанный AnalysisResult; он не запускает повторный обход.

## 3. Семантика статистики

Для каждой директории хранятся две области:
- direct: только файлы, непосредственно находящиеся в каталоге;
- subtree: файлы во вложенных каталогах, без файлов самой директории.

Total для визуализации вычисляется как direct + subtree. Размеры и количества учитываются отдельно для каждой FileCategory. Относительная доля категории рассчитывается относительно суммарного размера соответствующей области; при нулевом размере доля равна 0.

## 4. Символические ссылки и ошибки

Символическая ссылка на каталог отображается отдельным узлом, но целевой каталог повторно не обходится. Это предотвращает циклический обход и повторный учёт данных. Ссылки с недоступной или отсутствующей целью регистрируются как ошибки. Ошибка чтения одного вложенного каталога не должна автоматически прерывать обход остальных ветвей; ошибка открытия корневого каталога приводит к Failed.

## 5. Кэш навигации

DirectoryCacheManager хранит списки непосредственного содержимого каталогов и ограничивает число кэшированных каталогов. Кэш используется только для отображения и навигации. Он не является источником данных для полной статистики. Кнопка «Обновить» инвалидирует и перечитывает выбранный каталог, но не пересчитывает глобальную статистику — для актуализации статистики следует запустить полный анализ заново.

## 6. Границы реализации

Классификация на текущем этапе основана на расширении. MIME- и signature-based классификация не реализованы. Экспорт поддерживает JSON и TXT. Полная модель всех файлов не сохраняется: в результате анализа сохраняются дерево каталогов и агрегированная статистика.
