# Отчёт по курсовой работе

## Разработка оконного приложения для анализа дискового пространства файловой системы

## 1. Цель и постановка задачи

Цель работы — разработать оконное приложение на C++ для анализа использования дискового пространства файловой системы и наглядного представления результатов в виде дерева каталогов, таблиц и круговой диаграммы.

В соответствии с заданием программа должна анализировать выбранную директорию, вычислять статистику занимаемого пространства, отображать абсолютные значения и относительные доли, предоставлять статистику по категориям файлов и поддерживать несколько уровней детализации. Использование готовых библиотек, реализующих основной функционал анализатора дискового пространства, не допускается.

## 2. Используемые технологии

В проекте применены:
- C++17 — язык реализации;
- Qt 5 (Core, Widgets, Charts) — оконный интерфейс и визуализация;
- STL, включая `std::filesystem`, контейнеры и средства многопоточности;
- CMake — конфигурирование и сборка;
- CTest — запуск автоматических тестов;
- GitHub Actions — автоматическая сборка, тестирование и формирование переносимого пакета для Windows.

Обход файловой системы, хранение дерева каталогов, классификация файлов и расчёт агрегированной статистики реализованы в рамках проекта. Готовые анализаторы дискового пространства не используются.

## 3. Функциональные возможности

Приложение реализует следующие функции:

1. Выбор корневого каталога для анализа.
2. Итеративный обход каталогов и формирование дерева каталогов.
3. Определение размера файлов и классификация по расширению.
4. Подсчёт количества и суммарного размера файлов по категориям.
5. Раздельное отображение статистики текущего каталога и его поддерева.
6. Представление абсолютных размеров и процентных долей.
7. Отображение круговой диаграммы распределения занимаемого пространства по категориям.
8. Просмотр содержимого выбранного каталога и навигация по дереву без повторного полного сканирования.
9. Отображение прогресса, ошибок файловой системы и поддержка отмены анализа.
10. Экспорт агрегированных результатов в JSON и TXT.
11. Отображение признака неполного анализа, если отдельные объекты файловой системы не удалось прочитать либо анализ был отменён.

Символические ссылки на каталоги отображаются, но целевые каталоги рекурсивно не обходятся. Это предотвращает циклический обход и повторный учёт содержимого.

## 4. Архитектура приложения

Код разделён на слои с отдельной ответственностью.

### 4.1. Domain

Содержит модели и контракты предметной области: категории файлов, статусы сканирования, описание файлового объекта, статистику каталогов, узел дерева и контейнер результата анализа. Доменная модель не зависит от Qt.

### 4.2. Infrastructure

- **DirectoryScanner** — обходит файловую систему, строит дерево каталогов и заполняет статистику непосредственного содержимого.
- **FileClassifier** — определяет категорию файла по расширению.
- **DirectoryAggregator** — рассчитывает статистику вложенных каталогов по уже построенному дереву.
- **DirectoryContentsReader** — читает непосредственное содержимое каталога для таблицы.
- **DirectoryCacheManager** — кэширует локальные списки содержимого для интерфейса.
- **ExportManager** — сохраняет результаты анализа в JSON и TXT.

### 4.3. Application

**AnalysisPipeline** связывает сканирование и агрегацию. **ApplicationController** управляет жизненным циклом фонового анализа, отменой, прогрессом, ошибками и передачей результата интерфейсу.

### 4.4. Visualization и UI

**VisualizationModel** подготавливает данные статистики для диаграммы. **MainWindow** предоставляет элементы управления, дерево каталогов, таблицы, круговую диаграмму и средства экспорта.

## 5. Алгоритм анализа

1. Пользователь выбирает корневой каталог и запускает анализ.
2. Контроллер запускает работу в отдельном потоке, чтобы не блокировать GUI.
3. Сканер обходит каталог за каталогом, проверяет доступность объектов, определяет тип файлового объекта и классифицирует файлы.
4. Для каждого каталога формируется узел дерева и накапливается статистика файлов, непосредственно расположенных в нём.
5. Ошибки отдельных элементов регистрируются; если обход завершился не полностью, соответствующие узлы и их предки отмечаются как неполные.
6. После успешного завершения сканирования агрегатор проходит дерево снизу вверх и рассчитывает статистику вложенных каталогов.
7. Контроллер сообщает интерфейсу итоговый статус. Интерфейс отображает дерево, таблицы и диаграмму для выбранного каталога.
8. При экспорте сериализуется уже сформированный результат, повторный обход файловой системы не выполняется.

## 6. Организация статистики

Для каждого каталога поддерживаются две области статистики:

- **Direct** — количество и размер файлов, непосредственно находящихся в каталоге.
- **Subtree** — количество и размер файлов во вложенных каталогах; сам каталог в эту область не включается.
- **Total** — полная статистика, вычисляемая для отображения как сумма Direct и Subtree.

Для каждой области учитываются общее количество файлов, суммарный размер и статистика по категориям. Относительная доля категории рассчитывается относительно суммарного размера выбранной области. Если суммарный размер равен нулю, доля принимается равной нулю.

После завершения анализа сохраняются дерево каталогов и агрегированная статистика, а не полный перечень всех файлов. Это позволяет переходить между каталогами и показывать их статистику без повторного полного сканирования.

## 7. Обработка ошибок и особенности интерфейса

Недоступность отдельного каталога не должна автоматически прекращать анализ остальных доступных ветвей. Ошибка открытия корневого каталога приводит к неуспешному завершению анализа. При отмене сохраняется информация о том, что результат является частичным, и он не должен интерпретироваться как полный.

В таблице содержимого отображаются размеры поддеревьев и сводка по категориям непосредственных подкаталогов. Для предотвращения наложения подписей на круговой диаграмме числовые подписи вынесены из секторов; точные значения доступны при наведении, а легенда сохраняется.

Кнопка обновления перечитывает содержимое выбранного каталога для отображения, но не пересчитывает статистику всего дерева. Чтобы получить актуальную агрегированную статистику после изменения файловой системы, необходимо повторно выполнить полный анализ.

## 8. Тестирование

### 8.1. Автоматические проверки

В проект включены тесты следующих компонентов и сценариев:

- интеграционный конвейер сканирования, классификации и агрегации;
- жизненный цикл ApplicationController, отмена и повторный запуск;
- экспорт в JSON и TXT;
- преобразование статистики для визуализации;
- кэширование содержимого каталогов;
- чтение непосредственного содержимого каталога.

**Результат итогового запуска GitHub Actions:** успешно завершены этапы установки Qt, конфигурации CMake, сборки Release, запуска CTest, подготовки переносимого Windows-пакета и загрузки артефакта. ### 8.2. Ручные проверки

В ходе ручной проверки переносимой сборки были проверены базовые сценарии анализа, статистики, навигации и экспорта. В первоначальном протоколе были зафиксированы замечания к отображению таблицы содержимого, подписям круговой диаграммы, повторному сканированию при навигации, представлению неполных результатов и появлению консольного окна. В текущей версии реализованы соответствующие исправления: расширена таблица содержимого, подписи диаграммы заменены подсказками, навигация использует сохранённое дерево и кэш содержимого, неполнота анализа явно учитывается, а Windows-приложение собирается как GUI-приложение без отдельного консольного окна.

Некоторые редкие сценарии ручной приёмки — в частности, экспорт в каталог без прав записи и отдельные варианты недоступных директорий — не были подтверждены как завершённые в исходном протоколе. Их следует рассматривать как дополнительные проверки при необходимости расширенной приёмки.

## 9. Ограничения текущей реализации

1. Классификация файлов выполняется по расширению. Классификация по MIME-типу и сигнатурам файлов не реализована.
2. При изменении содержимого файловой системы локальное обновление списка каталога не обновляет агрегированную статистику; требуется полный повторный анализ.
3. Символические ссылки на каталоги не обходятся рекурсивно.
4. Сборка и автоматические тесты подтверждены в Windows CI, однако CI не заменяет проверку на каждой целевой конфигурации Windows и Linux.
5. Фактическое время анализа и потребление памяти зависят от количества файлов, характеристик накопителя и доступности объектов файловой системы.

## 10. Вывод

В результате работы разработано модульное оконное приложение на C++17 и Qt для анализа использования дискового пространства. Реализованы обход файловой системы, классификация файлов по расширению, дерево каталогов, агрегированная статистика по категориям, круговая диаграмма, таблицы, навигация и экспорт в JSON/TXT. Анализ выполняется вне GUI-потока; предусмотрены отмена и обработка ошибок файловой системы.

Архитектура разделяет предметные модели, инфраструктурные алгоритмы, управление процессом анализа и пользовательский интерфейс. Основные автоматические проверки и формирование переносимого Windows-пакета проходят в GitHub Actions. Известные ограничения реализации перечислены в отчёте и документации проекта.
