# Итоговый отчёт по курсовой работе

## Разработка оконного приложения для анализа дискового пространства файловой системы

## 1. Цель и постановка задачи

Цель работы — разработать оконное приложение на C++ для анализа использования дискового пространства файловой системы и представления результатов в виде дерева каталогов, таблиц статистики и круговой диаграммы.

В соответствии с заданием приложение должно анализировать выбранный каталог, отображать занимаемое пространство в абсолютном и относительном выражении, предоставлять статистику по директориям и категориям файлов, а также обеспечивать просмотр результатов с различной степенью детализации. Использование готового библиотечного решения, заменяющего реализацию анализатора файловой системы, не допускается.

## 2. Используемые технологии

- **C++17** — язык реализации.
- **Qt 5 Core, Widgets, Charts** — оконный интерфейс и визуализация.
- **STL**, включая `std::filesystem`, контейнеры, потоки и атомарные переменные.
- **CMake** — конфигурирование и сборка проекта.
- **CTest** — запуск автоматических тестов.
- **GitHub Actions** — автоматическая сборка, тестирование и подготовка переносимых пакетов.

Обход файловой системы, классификация файлов, построение дерева каталогов и агрегация статистики реализованы в проекте. Готовый анализатор дискового пространства не используется.

## 3. Функциональные возможности

Приложение реализует:

1. Выбор корневого каталога для анализа.
2. Итеративный обход файловой системы и построение дерева каталогов.
3. Получение размеров файлов и классификацию по расширению.
4. Подсчёт количества файлов и суммарного размера по категориям.
5. Раздельное отображение статистики текущего каталога и его вложенных каталогов.
6. Представление абсолютных размеров и относительных долей.
7. Отображение статистики в таблице и распределения размера в круговой диаграмме.
8. Просмотр содержимого выбранного каталога и навигацию по дереву без повторного полного сканирования.
9. Отображение прогресса, ошибок файловой системы и поддержку отмены анализа.
10. Экспорт агрегированных результатов в JSON и TXT.
11. Указание неполноты результата, если анализ отменён или часть объектов файловой системы недоступна.

Символические ссылки на каталоги отображаются, но их цели не обходятся рекурсивно. Это предотвращает циклический обход и двойной учёт содержимого.

## 4. Архитектура приложения

Код разделён на слои с отдельной ответственностью. В рамках завершающего этапа выполнена дополнительная работа по комментариям в ключевых частях реализации: уточнены комментарии главного окна (`src/ui/MainWindow.cpp`), конвейера анализа и агрегации (`src/application/AnalysisPipeline.cpp`, `src/infrastructure/aggregator/DirectoryAggregator.cpp`), семантики доменных перечислений (`src/domain/enums/FileCategory.h`, `FileSystemObjectType.h`, `ScanStatus.h`) и API статистики каталогов (`src/domain/models/DirectoryStatistics.h`). Эти изменения документируют существующую реализацию и не меняют архитектуру или программное поведение.

### 4.1. Domain

Содержит модели предметной области, перечисления и контракты компонентов: категории файлов, статусы сканирования, информацию о файловом объекте, статистику каталога, узел дерева, результат анализа и интерфейсы сканера, классификатора и агрегатора. Базовые доменные модели не зависят от Qt.

### 4.2. Infrastructure

- **FileClassifier** — определяет категорию файла по расширению.
- **DirectoryScanner** — выполняет итеративный обход файловой системы, строит дерево и заполняет Direct-статистику.
- **DirectoryAggregator** — вычисляет статистику вложенных каталогов снизу вверх.
- **DirectoryContentsReader** — читает непосредственное содержимое выбранного каталога для таблицы.
- **DirectoryCacheManager** — поддерживает ограниченный LRU-кэш списков содержимого для навигации.
- **ExportManager** — сохраняет результат анализа в JSON и TXT.

### 4.3. Application

**AnalysisPipeline** связывает сканирование и агрегацию. **ApplicationController** управляет жизненным циклом фонового анализа, запросом отмены, прогрессом, ошибками и передачей результата пользовательскому интерфейсу.

### 4.4. Visualization и UI

**VisualizationModel** подготавливает данные статистики для диаграммы с учётом выбранной области. **MainWindow** предоставляет выбор каталога, запуск и отмену анализа, дерево каталогов, таблицы, круговую диаграмму и экспорт.

## 5. Алгоритм работы

1. Пользователь выбирает корневой каталог и запускает анализ.
2. Контроллер создаёт рабочую задачу, не блокируя поток пользовательского интерфейса.
3. Сканер проверяет корневой путь и выполняет итеративный обход доступных каталогов.
4. Для каждого файла определяется размер и категория; статистика добавляется к непосредственному каталогу.
5. Ошибки чтения регистрируются, а обход доступных ветвей продолжается. При отмене фиксируется соответствующий статус результата.
6. После сканирования агрегатор обрабатывает дерево снизу вверх и рассчитывает статистику поддеревьев.
7. Контроллер уведомляет интерфейс о завершении и передаёт итоговый результат.
8. Интерфейс отображает дерево, таблицу статистики, список содержимого и диаграмму для выбранного каталога.
9. При экспорте сериализуется уже рассчитанный результат; повторный обход файловой системы не выполняется.

## 6. Организация статистики

Для каждого каталога различаются три области отображения:

- **Direct** — количество и размер файлов, непосредственно находящихся в каталоге.
- **Subtree** — количество и размер файлов во вложенных каталогах без файлов самого каталога.
- **Total** — сумма Direct и Subtree.

Для каждой области рассчитываются количество файлов, суммарный размер и значения по категориям. Относительная доля категории определяется относительно общего размера выбранной области. Если размер равен нулю, доли принимаются равными нулю.

После анализа сохраняются дерево каталогов и агрегированная статистика. Полный перечень всех файлов не используется как источник данных для повторного отображения статистики при навигации.

## 7. Инструкция пользователя

### 7.1. Windows x64

1. Скачать `DiskAnalyzer-Windows-x64.zip` со страницы [GitHub Releases](https://github.com/alaramia122/DiskAnalyzer_TRPO_Kursvaya/releases).
2. Распаковать архив в каталог, доступный для записи.
3. Запустить `DiskAnalyzer_TRPO_Kursovaya.exe`.

Пакет включает Qt runtime-библиотеки, развёрнутые `windeployqt`. Установка Visual Studio, компилятора или Qt для запуска не требуется.

### 7.2. Linux x86_64

1. Скачать `DiskAnalyzer-Linux-x86_64.AppImage` со страницы [GitHub Releases](https://github.com/alaramia122/DiskAnalyzer_TRPO_Kursvaya/releases).
2. Разрешить выполнение и запустить приложение:
   ```sh
   chmod +x DiskAnalyzer-Linux-x86_64.AppImage
   ./DiskAnalyzer-Linux-x86_64.AppImage
   ```

AppImage включает Qt runtime-библиотеки и плагины. Совместимость зависит от системных библиотек и графического окружения дистрибутива. Если обычный запуск блокируется поддержкой FUSE, можно попробовать:
```sh
./DiskAnalyzer-Linux-x86_64.AppImage --appimage-extract-and-run
```

### 7.3. Проведение анализа

1. Ввести путь к каталогу или выбрать его через кнопку «Обзор…».
2. Нажать «Начать анализ».
3. Дождаться завершения; при необходимости отменить анализ.
4. Выбирать каталоги в дереве и просматривать статистику.
5. Переключать область диаграммы: «Только здесь», «Вложенные каталоги» или «Весь каталог».
6. При необходимости сохранить результат через «Экспорт JSON…» или «Экспорт TXT…».

Кнопка «Обновить» перечитывает список непосредственного содержимого выбранного каталога, но не пересчитывает статистику всего дерева. После изменений файловой системы для актуализации статистики необходимо запустить полный анализ заново.

## 8. Тестирование

### 8.1. Автоматические проверки

В CTest зарегистрированы следующие тестовые программы:

- `AnalysisPipelineIntegrationTest` — интеграционная проверка сканирования, классификации и агрегации;
- `ExportManagerTest` — экспорт JSON/TXT;
- `ApplicationControllerTest` — жизненный цикл фонового анализа, отмена и повторный запуск;
- `VisualizationModelTest` — подготовка статистики для диаграммы;
- `DirectoryCacheManagerTest` — кэш навигации;
- `DirectoryContentsReaderTest` — чтение непосредственного содержимого каталога.

Единый workflow [Build, test and package](https://github.com/alaramia122/DiskAnalyzer_TRPO_Kursvaya/actions/workflows/build-release.yml) выполняет сборку и CTest для Windows x64 и Linux x86_64, а затем подготавливает переносимые пакеты и проверяет их запуск. По состоянию на 20.10.2026 успешно завершился запуск [workflow № 67](https://github.com/alaramia122/DiskAnalyzer_TRPO_Kursvaya/actions/runs/39408245073) для коммита [`ad0f941`](https://github.com/alaramia122/DiskAnalyzer_TRPO_Kursvaya/commit/ad0f941ca75f73aa522722aa8efa37cabab14699). В Windows x64 успешно выполнены конфигурирование, сборка, CTest, подготовка и smoke-test переносимого ZIP-пакета. В Linux x86_64 успешно выполнены конфигурирование, сборка, CTest, подготовка AppDir, упаковка Qt в AppImage и smoke-test запуска пакета. Оба задания завершились со статусом `success`. Публикация GitHub Release в этом запуске была пропущена, поскольку запуск инициирован обычным push, а не событием выпуска релиза. Smoke-test подтверждает запуск пакета в среде CI, но не заменяет ручную проверку всех сценариев интерфейса на целевых компьютерах.

При ручной приёмке дополнительно проверяются Direct/Subtree/Total, проценты, диаграмма, навигация, отмена, ошибки доступа и экспорт JSON/TXT. Успешный smoke-test подтверждает запуск процесса приложения в среде CI, но не заменяет проверку всех сценариев интерфейса на целевой машине.

## 9. Ограничения реализации

1. Классификация выполняется по расширению; MIME-тип и сигнатура содержимого не анализируются.
2. Символические ссылки на каталоги не обходятся рекурсивно.
3. Недоступное содержимое невозможно достоверно включить в расчёт; ошибки доступа могут приводить к неполной статистике.
4. Обновление локального списка содержимого не пересчитывает агрегированную статистику.
5. Совместимость AppImage зависит от системных библиотек и графического окружения Linux; CI не подтверждает работу на каждом дистрибутиве.
6. Время анализа и потребление памяти зависят от количества файлов, накопителя и доступности объектов файловой системы.

## 10. Заключение

В рамках курсового проекта разработано модульное оконное приложение на C++17 и Qt 5 для анализа дискового пространства файловой системы. Реализованы обход каталогов, классификация файлов по расширению, дерево каталогов, агрегированная статистика по категориям, таблицы, круговая диаграмма, навигация и экспорт JSON/TXT. Анализ выполняется вне основного GUI-потока; предусмотрены отмена и регистрация ошибок файловой системы.

Архитектура разделяет доменные модели, инфраструктурные алгоритмы, управление процессом анализа, визуализацию и пользовательский интерфейс. Для Windows и Linux настроена автоматическая сборка переносимых пакетов. Комментарии в ключевых модулях и доменных API уточнены без изменения классов и публичных интерфейсов. На коммите `ad0f941ca75f73aa522722aa8efa37cabab14699` автоматические сборка, тесты и smoke-test переносимых пакетов успешно прошли на Windows x64 и Linux x86_64. Ручная проверка всех пользовательских сценариев на физических целевых системах этим результатом не подтверждается. Известные ограничения и порядок ручной приёмки зафиксированы в документации проекта.
